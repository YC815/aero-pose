# 風阻姿勢大挑戰 v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 v1 的「定格單一姿勢」改成「相機畫面＋風流＋紅色迎風面，錄 10 秒動態，算平均省幾瓦」，並修好「往前彎就被踢回開始」的 bug。

**Architecture:** 先讀 v1.1 spec `docs/superpowers/specs/2026-10-16-aero-v1.1-dynamic-design.md`，它沒提的沿用 v1 spec `docs/superpowers/specs/2026-10-15-aero-pose-v1-design.md`。後端多推 `frame` 訊息（JPEG＋選中玩家的分割 mask）。前端以相機畫面為主，騎士只在後台計分和在結果頁重播。

**Tech Stack:** 同 v1：uv、FastAPI、mediapipe 1.1.x Tasks API、opencv 5、numpy 2；pnpm、Vite 8、TS 6、three 0.186、lil-gui、qrcode、vitest 5。

## Global Constraints

- 回覆、UI 文案、註解一律繁體中文；識別字用英文。
- Python 一律 `uv run`（在 `backend/`）；JS 一律 `pnpm`（在 `frontend/`）。
- **契約檔已由主控更新，不准改**：`backend/src/aero/config.py`、`backend/src/aero/types.py`、`backend/src/aero/sources/base.py`、`backend/src/aero/sources/__init__.py`、`frontend/src/types.ts`。需要改就在回報提出。
- 不准新增依賴。
- 多個 agent 同時在同一個工作目錄：**只動自己 task 列出的檔案**；**不准跑任何 git 指令**。
- 不准在前景跑不會結束的指令；不准用 playwright 或截圖；不准開啟相機（webcam 由使用者實測）。

## Task A：後端（選人黏著修正、分割 mask、frame 串流）

**Files:**
- Modify: `backend/src/aero/selector.py`、`pose.py`、`pipeline.py`、`preview.py`、`server.py`
- Test: 對應的 `backend/tests/test_selector.py`、`test_pose.py`、`test_pipeline.py`、`test_preview.py`、`test_server.py`
- 若有 `stillness_*`、`posing_max_s` 的殘留引用也一併清掉

**Interfaces:**
- Consumes：`types.py` 的 `PersonPose.mask`、`StepResult.selected_mask`（主控已加）
- Produces：

```python
# preview.py
def render_frame(r: StepResult, width: int = 960, mask_width: int = 192) -> dict
# 回傳 spec 的 FrameMsg：{"type":"frame","ts","jpeg_b64","width","height","mask_b64"|None,"mask_w","mask_h"}
```

**要求：**

1. **選人黏著（修 bug）**：`PlayerSelector.select`
   - 已鎖定時：只要有候選人的軀幹中心與上次距離 < 0.4 m 就選他，**不套用**距離範圍和站位區。有多個時選最近的。
   - 只有新鎖定時才套用範圍。
   - 測試要覆蓋這個情境：已鎖定的人 z 從 2.0 掉到 1.2（低於 `depth_near` 1.5）仍然被選中；同樣 z=1.2 但沒有鎖定時不選。
2. **分割 mask**：`PoseDetector` 開 `output_segmentation_masks=True`，每個 `PersonPose.mask` 填入對應 index 的 mask（float32 HxW）。
   - `Pipeline.step` 把選中者的 mask 放進 `StepResult.selected_mask`，沒選中時為 None。
   - 測試：用 FakeDetector 帶 mask，驗證有被傳遞。
   - pose 測試要能在沒有真影像時通過（黑圖 → 空 list）。
3. **render_frame**：
   - rgb 縮到寬 960（等比），轉 BGR 後用 cv2 編 JPEG（品質 70），再轉 base64。
   - mask 縮到寬 192（`cv2.INTER_AREA`），閾值 0.5 → 0 或 255 uint8，轉 bytes 再轉 base64。
   - **不鏡像**。
   - 測試：尺寸、base64 解碼後長度 = `mask_w * mask_h`、None mask 時 `mask_b64` 為 None。
4. **server**：
   - pipeline thread 每得到一個 StepResult，就呼叫 `render_frame`（在 pipeline thread 做，不要佔用 event loop），上限 20 fps，廣播給**所有** WS client。
   - 沿用既有的 per-client 有界 queue。frame 訊息很大，queue 滿了時優先丟舊的 frame，**不能讓 frame 擠掉 settings 或 status**：例如 frame 和其他訊息用不同 queue，或用最新值覆寫。
   - 測試：FakePipeline 產生帶 mask 的 StepResult，ws 收得到 `frame`；慢 client 時 status 仍會送達。
5. 跑全部後端測試：`uv run pytest -q`（不開相機）。

**Interfaces（Produces）：**

```ts
// game.ts
export interface GameInput { now: number; player: PlayerSkeleton | null; cameraOk: boolean; }
export class Game {
  constructor(getSettings: () => Settings);
  state: GameState;              // 初始 'ATTRACT'
  startProgress: number;         // ATTRACT 中舉手持續比例 0..1（沒玩家時 0）
  countdownLeft: number;         // COUNTDOWN 剩餘秒
  recordElapsed: number;         // RECORDING 已經過秒數
  recordLeft: number;            // RECORDING 剩餘秒
  resultLeft: number;
  onTransition: ((from: GameState, to: GameState) => void) | null;
  update(input: GameInput): GameState;
  forceStart(now: number): void; // 開發用：ATTRACT → COUNTDOWN
}
// session.ts
export interface SessionOptions {
  baselineM2: number;
  measure: (pose: RiderPose) => number;  // 由 main 注入：標準騎士＋曲柄固定 → 面積
  settings: () => Pick<Settings, 'cd' | 'speed_kmh' | 'air_density'>;
  sampleIntervalS?: number;              // 預設 0.1
}
export class RecordingSession {
  constructor(opts: SessionOptions);
  push(pose: RiderPose, t: number): void; // t = RECORDING 開始後的秒數，非遞減；每次都存 pose，跨過下一個取樣時間點才 measure
  readonly samples: readonly SessionSample[];
  latestWatts(): number | null;
  summary(durationS: number): SessionSummary;   // 沒有樣本時 throw
}
```

**規則（v1.1 spec 的流程章節）：**

- 任何狀態 `!cameraOk` → MAINTENANCE；MAINTENANCE 時恢復 → ATTRACT。
- ATTRACT：player 非 null 且 `handsUp` 連續 ≥ `start_hold_s` → COUNTDOWN；中斷就歸零；沒玩家時 `startProgress = 0`。
- COUNTDOWN：滿 `countdown_s` → RECORDING。
- RECORDING：滿 `record_s` → RESULT。
- COUNTDOWN、RECORDING：player 連續 null ≥ `lost_timeout_s` → ATTRACT，短暫 null 不算。
- RESULT：滿 `result_s` → ATTRACT。
- 進入每個狀態時重設對應計時器；每次轉移都呼叫 `onTransition`。update 的時間間隔不規則時（例如分頁休眠後 dt 很大）也要正確轉移，一次 update 最多轉移一個狀態即可。

**session：**

- 取樣時間點為 0、0.1、0.2…（第一次 push 就取樣 t=0）。
- 一次 push 跨過多個時間點時，只對最新的 pose 取一次樣，樣本的 t 記為最後跨過的那個時間點。不補插值，保持簡單。
- `watts` 用 `wattsSaved(baselineM2, area, settings())`。
- summary：
  - `meanWatts`、`meanAreaM2` 是樣本平均
  - `pct` 依 spec
  - `bestIndex` 是面積最小的樣本
  - `poses` 是所有 push 的 `{t, pose}`
  - `durationS` 由參數傳入
- 測試：
  - 用假 measure（例如回傳 `0.5 − pose.torsoPitch * 0.1`），驗證取樣次數：10 秒、每 1/30 秒 push → 101 個樣本，t = 0..10。
  - 驗證平均值、bestIndex、`latestWatts`、poses 數量。
  - 驗證大跳躍只取一次樣。
  - 沒樣本時 summary 會 throw。

```ts
// camera.ts
/** 「cover + 水平鏡像」把來源影像（原始方向，w×h）映射到螢幕 viewport（vw×vh）的轉換。 */
export interface CoverMap { scale: number; offsetX: number; offsetY: number; srcW: number; srcH: number; vw: number; vh: number; }
export function coverMap(srcW: number, srcH: number, vw: number, vh: number): CoverMap;
export function screenToSource(m: CoverMap, sx: number, sy: number): [number, number];   // 已含鏡像
export function sourceToScreen(m: CoverMap, u: number, v: number): [number, number];
export function decodeMask(b64: string, w: number, h: number): Uint8Array;               // 長度不符時 throw
export class CameraView {
  constructor(container: HTMLElement);   // 自己建 canvas，全螢幕，最底層
  setFrame(msg: FrameMsg): void;         // 用 createImageBitmap 非同步解碼；舊的解碼完成晚於新的時要丟棄；不累積 bitmap（要 close）
  readonly map: CoverMap | null;         // 目前畫面的映射
  readonly mask: { data: Uint8Array; w: number; h: number } | null;   // 最新 mask（原始方向）
  setDimmed(on: boolean): void;          // RESULT 時把相機畫面壓暗
  dispose(): void;
}
// windfield.ts
export class HeatField {
  constructor(w: number, h: number);     // mask 解析度
  deposit(u: number, v: number, amount: number): void;   // 以原始方向的 mask 座標累積
  decay(dt: number): void;               // 每秒衰減到約 13%
  readonly data: Float32Array;
  resize(w: number, h: number): void;    // mask 尺寸改變時清空重建
}
export class WindField {
  constructor(container: HTMLElement, camera: CameraView);   // 自己建 overlay canvas，疊在相機上方
  setActive(on: boolean): void;          // 淡入淡出約 0.5 s
  update(dt: number): void;              // 推進粒子、命中判定、熱度、繪製
  dispose(): void;
}
```

**視覺要求（v1.1 spec 的風流章節）：**

- 風帶：約 300–500 條藍色（#38bdf8 系）發光短線，加法混合。
  - 從觀眾這側（螢幕前方，大且快）往畫面深處（玩家平面）透視收斂。
  - 用簡單的 3D 投影：粒子有 (x, y, z)，z 從近到遠，螢幕位置 = 消失點 + (x, y) × f / z。
- 粒子抵達玩家平面時，換算成 mask 座標（`screenToSource` 再按比例轉到 mask 尺寸）：
  - mask 值 > 0：在命中點 `deposit`（可帶一點擴散），粒子做短暫散開的濺射後回收。
  - 沒打到：繼續往後流走、淡出後回收。
- 紅色層：
  - HeatField 每幀 `decay`。
  - 畫到一張與 mask 同解析度的離屏 canvas：紅色、alpha 依熱度、可帶模糊。
  - 再依 CoverMap（含鏡像）放大疊到螢幕上。
  - 要明顯但看得到底下的人。
- 效能：60 fps，每幀零配置（重用 typed array 和 ImageData）。
- 不使用 three.js 也可以，Canvas2D 足夠。

**測試：**

- coverMap 與鏡像：
  - 來源 1280×720 進 1920×1080 → scale 1.5、無 offset。
  - 螢幕左上角對應來源右上角（鏡像）。
  - `screenToSource(sourceToScreen(p)) ≈ p`。
  - 直式 viewport 會裁左右。
- decodeMask：長度檢查。
- HeatField：deposit 後值增加；decay 1 秒後約剩 13%（±3%）；resize 會清空。
- 命中判定抽成純函式，例如 `hitMask(mask, w, h, u, v)`：mask 外回 false，內回 true，座標越界回 false。
